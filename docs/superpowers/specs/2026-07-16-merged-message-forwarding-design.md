# 多条消息合并转发设计

## 目标

用户可在一个会话中选择多条消息并转发给一个或多个联系人或群组。收件方收到一张可展开的“聊天记录”卡片，而不是连续的普通消息。

## 范围

- 复用既有收件人选择弹窗与发送接口。
- 在消息列表中提供选择模式、单条勾选、全选/取消与“合并转发”操作。
- 新增前端消息类型 `merged_forward`。它的 `content` 是版本化 JSON 快照，包含被选消息的类型、内容、发送者展示名及时间。
- 在消息项中将此类型渲染为摘要卡片；展开后按原始顺序展示文本、图片与文件的可读摘要。
- 服务端继续把 `type` 与 `content` 当作通用字段持久化和广播；不新增表、不迁移数据库。

## 不在第一版范围内

- 原消息实时追溯、跳转、转发关系查询。
- 嵌套合并转发、逐条转发模式。
- 被转发消息撤回/删除后同步改变卡片内容。
- 复杂媒体下载、卡片内消息操作或跨会话权限校验。

## 数据格式

`content` 使用如下结构，保留 `version` 以便未来兼容演进：

```json
{
  "version": 1,
  "title": "聊天记录",
  "messages": [
    {
      "id": "123",
      "type": "text",
      "content": "你好",
      "senderName": "小青",
      "timestamp": 1780000000000
    }
  ]
}
```

前端解析失败时展示“聊天记录无法加载”的安全降级文本，不阻断其他消息渲染。

## 交互与数据流

右键菜单新增“多选”入口。选择模式激活后，每条未撤回消息显示复选框；底部操作栏显示选中数量，并提供取消与合并转发。确认收件人后，发送一条 `merged_forward` 消息。现有 REST 和 WebSocket 链路原样携带该类型；本地聊天 store 同样插入这条卡片消息。
