# 群文件空间加固设计

## 目标

修复群文件空间的管理员保存聊天附件、会话切换、存储清理、迁移可靠性及面板请求一致性问题；不新增数据库表。

## 权限边界

管理员保存聊天附件时，客户端提交 `message_id`、`file_id` 与目标文件夹。服务端必须同时验证：

1. 请求者是目标群的 owner 或 admin；
2. `message_id` 对应的消息属于该目标群关联的会话；
3. 消息类型为 `file`，其内容中解析出的附件 ID 与 `file_id` 一致；
4. 目标文件夹属于该群文件空间。

校验通过后，服务端创建复用原 `storage_path` 的群文件引用。不按 `source=chat` 或任意群成员身份放行源文件，避免跨群文件 ID 被猜测后泄露。

## 会话与请求状态

`ChatWindow` 监听会话 ID 变化时关闭群文件面板并清空待引用文件/消息。`GroupFilesPanel` 为每次列表请求分配递增序号，仅接收与最新序号匹配的响应，避免旧群数据覆盖新群。

## 存储生命周期

单文件删除、批量删除及群文件删除共享同一存储清理语义：软删除记录后，仅当没有活跃记录引用同一 `storage_path` 时才删除物理对象。

同一路径的创建引用与删除引用在进程内按路径串行化；数据库记录修改和引用计数检查置于事务中，物理删除在确认无活跃引用后执行。该设计保证当前单实例 SQLite 部署中不会出现“新引用已创建但物理文件被旧删除请求移除”的窗口。

## 迁移与失败行为

`MigrateFileSpaces` 的失败不再仅记录日志后继续启动。启动初始化应返回错误并终止，确保用户不会在作用域数据未完成回填时运行新查询规则。迁移保持幂等：空 scope 和 `user/0` 历史个人空间都回填为 `user/user_id`。

## 上传失败和 UI 反馈

成员上传成功但附加到群失败时，原个人文件保留，客户端明确提示“已保留在文件箱，可重试加入群文件”。文件管理界面不隐式删除用户已成功上传的数据。

AI 徽章补充暗色主题下可读的前景色。保存聊天附件前继续捕获不符合附件 JSON 格式的内容并给出提示；服务端以 `message_id` 再次校验，不信任客户端解析结果。

## 验证

- 服务层测试：管理员可保存同群其他成员的附件；不同群/伪造消息/非管理员均拒绝。
- 并发测试：引用创建与删除同路径时，活跃引用的存储对象不会被删。
- 迁移测试：回填失败会让应用初始化返回错误；有效历史记录仍幂等回填。
- 前端测试：会话切换清理面板状态；旧列表响应不覆盖新群；attach 失败显示保留提示；暗色徽章存在明确前景色。
