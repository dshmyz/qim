# 群文件空间设计

## 目标

为群聊提供独立的共享文件空间：成员可上传和下载，群主与管理员可整理目录、移动和删除文件；群详情与聊天顶部进入同一个文件中心。实现必须复用并泛化现有文件能力，避免新增专用表，同时为频道和项目空间扩展预留统一模型。

## 核心模型

现有 `files` 和 `folders` 演进为按空间归属的资源，不新增表。

- `files` 新增 `scope_type` 与 `scope_id`。`user` 表示个人空间，`group` 表示群空间；以后可增加 `channel`、`project`。`user_id` 明确表示上传者/创建者，而不再是唯一访问权限来源。
- `folders` 新增相同的空间字段，继续复用 `parent_id` 建立目录树。旧个人文件夹回填为 `user` 空间，群文件夹使用 `group` 空间。
- `files.folder_id` 继续引用 `folders`。服务端确保文件与其目标文件夹属于相同空间，禁止跨空间移动和目录循环。
- `group_documents` 保持 AI 知识库绑定的专用职责；普通群文件不写入该表，也不触发解析、向量化或处理状态。

## 文件空间模块

新增一个深的“文件空间”模块作为权限和资源操作的唯一入口。其接口只接收 `scope(type, id)` 与当前用户，并提供列表/搜索、上传后归属、下载授权、目录创建、移动、删除、聊天附件转存等操作。

模块内部负责：群成员与角色校验、个人空间所有权兼容、目录空间校验、分页与排序、引用文件生命周期。路由和前端不直接拼接 GORM 查询或自行判断角色。

## 交互与权限

- 群详情新增“群文件”入口；群聊天顶部新增文件夹图标；两者打开同一群文件中心。
- 文件中心提供目录树、全部文件、搜索、上传和分页文件列表，展示名称、上传者、时间和大小。
- 所有群成员可上传、下载；仅群主/管理员可创建目录、移动文件和删除群文件。
- 聊天附件不会自动同步。管理员可从聊天附件菜单选择“保存到群文件”，再选择目标目录。
- 转存创建一条新的逻辑文件资源，复用原文件的 `storage_path` 与校验和，标记 `source=shared_reference` 和 `source_id` 为原文件 ID；不复制二进制数据。
- 删除共享引用只删除该群文件记录。物理对象只有在没有任何有效资源引用时才可清理，聊天附件、个人文件和其他共享引用均不受影响。

## 迁移与边界

- 迁移为所有旧 `files` 与 `folders` 回填 `scope_type=user`、`scope_id=user_id`，并为 `(scope_type, scope_id, folder_id)` 建索引。
- 个人文件 API 在迁移后仍只访问用户空间，保持现有行为和 URL 兼容。
- 第一阶段不包含在线编辑、版本历史、预览转换、聊天附件自动汇总或 AI 知识库自动绑定。
- 第二阶段完成聊天附件手动转存及群详情/聊天双入口的体验集成。

## 验证

- 个人文件和文件夹迁移后可正常列出、移动、下载和删除。
- 群成员只能访问自己所在群的文件；管理员权限覆盖目录管理和删除，普通成员无权执行这些操作。
- 文件无法移动到不同空间的目录，目录无法移动到自身或后代。
- 聊天附件转存后可在群文件中心下载；删除该共享引用后，原聊天附件仍可下载。
- AI 知识库接口只返回 `group_documents`，不把普通群文件纳入向量化流程。
