# 群助手 / 分身 / 群Bot / 外部Agent 的「知识库 vs 记忆」对照清单

> 本文档厘清 QIM 各 AI 角色各自的**知识库（显式材料）**与**记忆（对话提炼结论）**，
> 归属、存储位置、namespace 隔离、开关与隐私边界。**三者（群知识库 / 群记忆 / 用户笔记）
> 是独立 service、独立存储、刻意隔离**，不要混为一谈。
>
> 维护依据：截至 2026-08，`qim-server/service` 各服务实现。改任一处请同步更新本文。

---

## 0. 一句话总览

| 角色 | 知识库（显式材料） | 记忆（对话提炼） |
|---|---|---|
| **群助手**（smart_reply） | ✅ 群文档库 `GroupDocumentService` | ✅ 群记忆 `GroupMemoryService` |
| **分身**（AvatarService） | ✅ 群知识库 + **主人笔记**（`notes` 开关） | ✅ `AvatarMemoryService` |
| **群 Bot**（MessageService internal_ai） | ✅ 创建者笔记（`use_creator_notes`） | ⚠️ 复用群/分身记忆链路 |
| **外部 agent**（CLI / MCP） | ✅ 用户笔记（`search_notes` 等） | ❌ 不主动记，靠笔记沉淀 |

---

## 1. 三个绝不能混淆的概念

| 概念 | 是什么 | 服务实现 | 存储 |
|---|---|---|---|
| **群知识库** | 群显式上传的文档（权威材料） | `GroupDocumentService` | 元数据 SQLite `qim.db` + 向量 gracedb |
| **群记忆** | 从群对话提炼的共识/约定/偏好 | `GroupMemoryService` | gracedb，`Namespace="group_assistant"` |
| **用户笔记** | 个人私有长期知识（用户自写） | `NoteVectorService` | gracedb，`user_notes_<userID>` 集合 |

三者写入来源不同（**显式上传 / 自动提炼 / 用户自写**）、授权逻辑不同、sts存储/namespace 不同，
任何一个都不能被当作另一个的替换品。

---

## 2. 知识库 vs 记忆 —— 本质区别

| 维度 | 知识库（`GroupDocumentService`） | 记忆（`GroupMemoryService`） |
|---|---|---|
| 本质 | 事实性**原文**材料 | LLM 反射产出的**结论**（摘要） |
| 来源 | 用户显式上传文件 | 群对话动态提炼 |
| 写入 | 上传 → 解析分块 → 向量化 | `Remember` / `ConsolidateGroupMessage`（三层门控） |
| 内容形态 | 原文 + 分块片段 | 压缩摘要（`ref.Summary`）+ 重要度/themes/entities |
| 增删 | 显式上传/删除，有处理状态机 | 自动增删、可 `ForgetAll` 清空、随时间折叠 |
| 召回 | `unifiedKnowledge.Search(groupID, query, topK)` | `Recall(groupID, query, topK)` |
| 注入前缀 | `📚 群知识库相关内容` | `💡 群聊记忆` |
| 回答定位 | "事实是什么"（原文引用，准确） | "这个群默认怎么做事"（结论） |

**一句话**：知识库是"群放进来的权威材料"，记忆是"系统从对话提炼出的共识"。一个是原文，一个是结论。

## 3. 群助手（smart_reply 引擎）

- **引擎结构**：`SmartReplyEngine`（[handler/smart_reply_handler.go:21](qim-server/handler/smart_reply_handler.go:21)）
  持 `unifiedKnowledge`（知识库）+ `groupMemorySvc`（记忆）。

### 3.1 群记忆
- **注入**：`SetGroupMemoryService` → `groupMemorySvc`
- **写入**：`maybeRememberGroupMessage` → `ConsolidateGroupMessage`（三层门控：
  `looksMemorable` 规则预筛 → 向量去重 → LLM 质量门）
- **召回**：回复时 `Recall(groupID, userContent, 2)` 注入 `💡 群聊记忆`
- **存储**：gracedb `Namespace="group_assistant"` + `UserID=<groupID>`
- **管理接口**（群主可查/清空/搜/删本群记忆）：
  - `GET  /groups/:id/group-memories`
  - `POST /groups/:id/group-memories/search`
  - `DELETE /groups/:id/group-memories` / `/:memory_id`

### 3.2 群知识库
- **注入**：`unifiedKnowledge`（`UnifiedKnowledgeService` 包装 `GroupDocumentService`）
- **召回**：回复时 `unifiedKnowledge.BuildContext(question, ctx.Group.ID)` 注入 `📚 群知识库相关内容`
- **存储**：文档元数据 SQLite + 分块向量 gracedb
- **联动**：`unifiedKnowledge.Search(...)` 结果会作为 `ConsolidateGroupMessage` 的折叠素材（knowledge 参数），
  即"知识库能帮助生成记忆"，但两者本身不同。

## 4. 分身（AvatarService）

- **注入**：`SetRAGServices(noteVectorSvc, avatarMemorySvc, ...)`（[avatar_service.go:60](qim-server/service/avatar_service.go:60)）
- **笔记 RAG**（主人笔记）：
  - 检索：`SearchNotes(input.UserID, input.Message, 3)`（[avatar_reply_graph.go:338](qim-server/service/avatar_reply_graph.go:338)）
  - **scope = 主人 `input.UserID`**，只读主人自己笔记
  - **开关**：`AvatarKnowledgeScope.Notes`（`notes` 字段）
  - 前端：`AvatarKnowledgeSettings.vue`「笔记」checkbox
- **记忆**：`AvatarMemoryService`，`Namespace="avatar"` 按 `userID` 键
- **知识库**：也接 `GroupDocumentService`（当前会话所在群），但**只检索当前会话所在群**，不遍历全部成员群

---

## 5. 群 Bot（MessageService internal_ai）

- **注入**：`SetNoteSearcher` → `s.noteSearcher.SearchNotes(bot.CreatorID, content, 3)`（[message_service.go:363](qim-server/service/message_service.go:363)）
- **scope = 创建者 `bot.CreatorID`**（机器人创建者本人）
- **开关**：`BotConfig.UseCreatorNotes`（`use_creator_notes`）
  - 前端：`CreateBotWizard.vue` / `BotConfigDialog.vue`
  - 仅 `internal_ai` 模式生效；`external_webhook` 模式由外部 agent 自行决定
- **命中展示**：标题/分数写入 `message.Extra`，前端渲染"知识来源"折叠标签

---

## 6. 外部 agent（CLI / MCP）

- **不是"内部回复链路"，而是外部主动访问**。
- **笔记读写/语义检索**：`list_notes` / `get_note` / `create_note` / `update_note` / `search_notes`（需 user JWT）
  - CLI：`qim note list / get / create / update`
  - MCP：`--user-token` 传用户 JWT
- **scope = 登录用户本人**（`user_notes_<userID>` 集合）
- **不主动记忆**：靠用户把有价值结论写进笔记沉淀，后续经 `search_notes` 召回。

---

## 7. 隐私隔离原则（写代码时的硬约束）

1. **笔记是私有用户级数据**，只按单一用户 scope 检索（`input.UserID` / `bot.CreatorID` / 登录用户）。
2. **不要把用户笔记塞进群知识库（`unifiedKnowledge`）**：那是按 `groupID` 的共享知识，会让 A 的私密笔记
   暴露给同群 B/C/D。即使要做"某人笔记给群用"，也必须有明确的单用户 scope 与授权，不能混入群检索。
3. **群记忆与分身记忆刻意隔离**（[group_memory_service.go:9](qim-server/service/group_memory_service.go:9) 注释）：
   **杜绝跨上下文（私聊→群）泄露**。`group_assistant` 与 `avatar` 是不同 namespace。
4. **全局记忆若要做**：建议复用"知识库（显式可信） vs 记忆（隐式提炼）"两层模型，而非把各组混为一库。

## 8. 存储落点速查

| 数据 | 位置 | 说明 |
|---|---|---|
| 群文档元数据 | SQLite `qim.db`（`GroupDocument` 表） | 上传记录、处理状态 |
| 群文档分块向量 | `./data/gracedb` | `unifiedKnowledge` 集合 |
| 群记忆 | `./data/gracedb` | `Namespace=group_assistant` |
| 分身记忆 | `./data/gracedb` | `Namespace=avatar` |
| 用户笔记向量 | `./data/gracedb` | `user_notes_<userID>` 集合 |
| 群对话消息 | SQLite `qim.db` | 消息表 |

> 向量库路径配置：`config.yaml` → `vector.path`（默认 `./data/gracedb`）。备份/迁移看这个目录，不是 `qim.db`。
